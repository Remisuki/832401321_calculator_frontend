# 算页 · 计算器前端

软件工程作业：前后端分离计算器。前端负责输入、按钮交互、发送请求和显示后端结果，**不在浏览器中计算表达式**。

## 1. 项目状态与技术栈

- 原生 HTML、CSS、JavaScript，无框架、无外部字体、无第三方运行依赖。
- 使用浏览器 Fetch API 与 Python 后端交换 JSON。
- 本项目可独立作为一个 GitHub 仓库提交；后端需要另建一个仓库。
- 当前完成本地运行版；本仓库没有预先部署好的公网地址。
- 后端是 Python 标准库 HTTP 服务，**不是 Flask**。之前关于 Flask/Gunicorn/Neon 的方案尚未在这版实现。
- 需要现代浏览器，如近期版本的 Chrome、Edge、Firefox；用 Python 3.9+ 启动本地静态文件服务。

## 2. 功能

| 功能 | 使用方式 |
|---|---|
| 计算器按钮 | 数字、小数点、加减乘除、括号、AC、退格、等号 |
| 键盘输入 | 点击输入框直接输入；Enter 或 = 计算；Esc 清空 |
| 光标编辑 | 点击按键会在光标处插入，选中文本时替换选中部分 |
| 结果展示 | 显示后端返回的十进制结果；修改表达式后清除旧结果 |
| 错误反馈 | 空输入、非法表达式、除零、断线、超时均有中文提示 |
| 计算历史 | 从后端数据库读取，按时间倒序，每页 5 条 |
| 指定记录删除 | 调用后端接口删除，再重新读取数据库状态 |
| 历史复用 | 点击历史算式填回输入框；再次计算仍必须请求后端 |
| 界面适配 | 桌面双栏、手机单栏、键盘焦点和状态提示 |

## 4. 从零开始运行

先启动后端，再启动前端。两者是两个独立服务，需要保持两个命令窗口开启。

### 方法 A：Windows 双击启动

在 Windows 文件资源管理器中打开本文件所在文件夹，双击 `start.bat`。聊天窗口中的文件预览只显示脚本内容，不等于运行。

随后在浏览器中打开 <http://localhost:5500>。后端应运行在 <http://localhost:5000>。

如果使用完整成果文件夹，也可以双击外层的 `start-backend.bat` 和 `start-frontend.bat`。

### 方法 B：终端运行

在本文件所在的 `frontend` 文件夹中打开终端：

```powershell
python -m http.server 5500 --bind 127.0.0.1
```

打开 <http://localhost:5500>。按 Ctrl+C 停止服务。

不需要运行 npm install，也不需要直接双击 index.html。请使用上述 HTTP 地址访问，否则浏览器来源与后端允许列表不匹配。

## 5. 前后端连接配置

编辑 `config.js`：

```javascript
window.CALCULATOR_CONFIG = Object.freeze({
  apiBaseUrl: "http://localhost:5000/api",
  requestTimeoutMs: 15000,
});
```

- `apiBaseUrl`：后端地址，包含 `/api`，例如部署时换为实际 HTTPS 后端地址。
- `requestTimeoutMs`：请求超时，默认 15000 毫秒。
- 前端配置对访问者公开，不能放数据库密码、访问密钥等信息。
- 修改后在浏览器按 Ctrl+F5 强制刷新。
- 前端换端口或公网域名时，也必须更新后端的 `ALLOWED_ORIGINS`。
- 线上前端不能继续使用 localhost；localhost 指的是每个访问者自己的电脑。
- HTTPS 前端必须连接 HTTPS 后端，避免浏览器阻止混合内容。

前端不直接连接数据库，因此没有前端数据库初始化步骤。数据库初始化由后端启动程序自动完成。

## 6. 使用的接口

| 方法与路径 | 用途 |
|---|---|
| POST /api/calculate | 提交 `{"expression":"(1+2)*3"}` |
| GET /api/history?limit=5&offset=0 | 分页读取历史 |
| DELETE /api/history/{id} | 删除指定记录 |

计算结果使用字符串，例如 `"result": "0.3"`，避免前端再次转换为浮点数导致精度损失。

历史接口返回 `{success, records, total, limit, offset}`。这与初版的纯数组响应不同，**更新时需要同时更新前端和后端**。

## 7. 验收步骤

1. 输入 `1+2*3` 得到 7；输入 `(1+2)*3` 得到 9。
2. 输入 `-5+8` 得到 3；输入 `3*-2` 得到 -6。
3. 输入 `0.1+0.2` 得到 0.3；输入 `1.5+2.25` 得到 3.75。
4. 输入 `1/0` 或 `1++`，应显示中文错误，不增加历史记录。
5. 用按钮输入 `(12+8)÷4`，点击等号得到 5。
6. 使用 AC、退格、光标插入、Enter 和 Esc，检查输入交互。
7. 完成超过 5 次计算，翻页并检查总记录数。
8. 点击历史表达式，修改后重新计算；再删除指定记录。
9. 刷新页面和重启后端，确认已有记录仍存在、删除的记录不会回来。
10. 停止后端，输入一个新算式，必须报连接错误，不能生成新的结果。

仓库中的后端自动测试使用临时数据库，不会清空你的个人计算记录。前端脚本语法可选检查：`node --check app.js`；Node.js 不是运行页面的必需条件。

## 8. 常见问题

| 问题 | 处理 |
|---|---|
| 打开 bat 看到代码 | 在文件资源管理器中双击运行，不是在编辑器里预览 |
| 页面打不开 | 确认前端窗口仍开启，端口是 5500 |
| 连接失败 | 确认后端已启动，检查 config.js 地址及后端 ALLOWED_ORIGINS |
| 历史接口版本不匹配 | 关闭旧后端窗口，重新启动新版；页面按 Ctrl+F5 |
| 界面还是旧版 | 强制刷新，确认打开的是正确文件夹对应的服务 |
| 端口被占用 | 不要重复启动同一服务；关闭自己之前启动的窗口后再运行 |
| 长时间等待后超时 | 先刷新记录确认是否已保存，再决定是否重新提交 |
| 公网页面报错 | 检查 HTTPS、后端域名、跨域允许来源和服务状态 |

## 9. GitHub 上传与部署

将本文件夹的源码、`config.js`、`start.bat`、README、代码规范和 `.gitignore` 放在前端仓库根目录。网页手动上传时，.gitignore 不会替你筛选文件。

GitHub Pages 可托管前端：Settings → Pages → Deploy from a branch → 选择源码分支及 /(root) → Save。**GitHub Pages 不会运行 Python 后端。**

必须先准备真正可用的线上后端，再填写 config.js 中的地址，并在后端允许该前端来源。例如页面为 https://用户.github.io/仓库名/，其 Origin 是 https://用户.github.io，不能带仓库路径。

正式提交前补充博客中的前端仓库链接、后端仓库链接、两个代码规范链接和公网访问地址；不要用虚构地址代替。

## 10. 实现说明与限制

前端没有 eval、表达式解析器或最终结果计算逻辑，也不使用 LocalStorage 保存计算历史。所有历史来自数据库接口。历史文字通过 textContent 写入，避免作为 HTML 解释。发送计算期间会禁用重复提交。

当前历史为共享记录，没有账号隔离；能访问后端的人可以查看或删除共享记录。前端连接标志反映最近请求结果，不是持续监控。长除法遵循后端的 28 位有效数字规则，本项目不是财务或科学高精度计算工具。
